# SCANN 原生FITS在线标注协作平台设计方案

## 〇、 核心目标与定位
抛弃重型的 Label Studio，针对天文/图像发现任务的特殊性，构建一个**轻量化、原生FITS支持、UI/UX优先**的在线协作标注平台。
确保FITS图像的实时调节与多图闪视（Blink）不仅流畅，而且完全符合本地数据集规范，优化弱小目标（如彗星、瞬变源、小行星）的发现体验。

---

## 一、 UI/UX 优先设计方案 (以天文发现为中心)

界面采用**暗黑主题 (Dark Mode)**，减少视觉疲劳，高亮显示微弱星体和标注。

### 1. 界面布局 (Layout)
* **顶栏 (Header):**
  * 当前目标/图像组的名称（如 `PGC 17069`）。
  * 用户状态（当前登录用户、退出登录）、协作状态（当前在线分布式情况）、保存状态。
* **左侧工具栏 (Tools):**
  * 移动/缩放 (Pan/Zoom)、点标注 (Point)、框标注 (BBox)、多边形 (Polygon)、删除工具。
* **中央主画布 (Main Canvas):**
  * **核心交互:** 无缝平移和无极缩放。支持多图层叠加（图像层 + 标注层 + 辅助十字线）。
  * **快捷键 Blinking (闪视):** 按下 `Space` 或 `Tab` 键，在【旧图 (old)】 👉 【新图 (new)】 👉 【带标记新图 (new_marked)】之间毫秒级无缝切换。需建立图像预加载机制。
* **右侧控制台 (Inspector):**
  * **直方图与拉伸 (Histogram & Stretch):** 提供实时交互的直方图，双滑块控制 `Min` 和 `Max` 参数，一键应用 `ZScale / MinMax / Asinh / Log` 拉伸。
  * **反色开关 (Invert):** 快速切换黑白显示。
  * **标注列表 (Annotations):** 当前画布上的目标列表，支持点击定位、修改分类（如 Positive/Negative/Artifact）。
  * **版本历史 (Version History):** 当前图像的标注提交历史记录，支持查看之前用户（或自己）的多次提交记录、比对与版本回滚。
* **底栏 (Dataset Navigator):**
  * 图像队列幻灯片（Thumbnail track），支持左右箭头快速切换上一个/下一个观测目标。

## 二、 架构与技术选型 (主打轻量与极速开发)

优先复用成熟的开源组件，实现快速开发迭代：

### 1. 前端架构 (Frontend)
* **基础框架:** **Vue 3 (Composition API) + Vite + TailwindCSS**
  * *理由:* 启动极快，Tailwind 极大地加速了定制化 UI 绘制，且打包体积小。
* **画布与影像渲染:**
  * **标注层: Konva.js** (或 `vue-konva`)。非常成熟的 2D Canvas 库，自带图层管理、拖拽、缩放、绘制，能省去大量的底层画布开发时间。
  * **FITS 操作层: fits.js + WebGL (或纯 Canvas ImageData)**。由前端直接请求 FITS 的原始数据流（解压后的 Float32 Array），在客户端使用 WebGL Shader 或者 Web Worker 进行实时的直方图拉伸和反色。
  * *(备选方案):* 后端 Python 根据前端传来的 Stretch 参数，实时生动态 8-bit PNG/JPEG 传给前端。作为 MVP 阶段的快速实现手段。

### 2. 后端架构 (Backend)
* **API 与服务:** **FastAPI (Python)**
  * *理由:* 原生异步，性能极高。完全契合现有的 Python 技术栈，代码复用率高。
* **FITS 处理库:** **Astropy**
  * 提供 `ZScaleInterval` 等标准天文拉伸算法的基准数据，提供头文件解析。
* **数据库/持久层:** **SQLite/PostgreSQL + JSON 文件架构**
  * **用户与基础业务:** 存储用户凭证、身份角色（Admin/Annotator），以及防冲突 Token 快照。
  * **标注与版本控制:** 将传统单点覆盖保存改为**追加式的版本快照 (Revision) 设计**，记录每次提交的时间戳、用户ID、变更快照。标注最新稳定态同步写入同名 JSON 归档文件（算法直取），而历史回退等由数据库负责。

## 三、 本地数据集架构融合方案

完全遵守 SCANN 现有的本地文件结构：

```text
dataset/
    old/           -> 历史参考图 (PGC 17069.fts)
    new/           -> 待检新图 (PGC 17069.fts)
    new_marked/    -> 用于参照的带标记的已知新图 (PGC 17069.fts)
```

### 核心处理逻辑：
1. **任务分发:** 后端 FastAPI 扫描 `dataset/new` 文件夹，将同名文件（如 `PGC 17069.fts`）作为**一个联合任务 (Session)** 下发给前端。
2. **预加载 (Preload):** 前端收到任务后，立刻并行请求 `old`, `new`, `new_marked` 三个视图的数据流进入内存。
3. **坐标系对齐 (WCS Alignment):** 三张图的像素坐标原则上是一致的，Konva.js 只需要维护**唯一的一个标注图层 (Annotation Layer)**。在切换底图 (Blink) 时，标注框依然保留在相同像素位置上方。
4. **标注结果与版本控制 (Save & Revision):** 前端提交操作后，带上 JWT 用户令牌和完整的标注状态。后端不覆盖原记录，而是创建一条**新的历史版本节点（Revision ID）**，关联到当前协作用户。数据库记录固化后，自动依据最高优先级的最新版本，覆写至 `positive/` 中符合算法读取标准的本地 JSON 文件。

## 四、 核心功能特色实现路线

### 1. FITS 直方图实时拉伸与反色
* **提取极值:** 后端 FITS 加载时，计算出图像的物理最小值和最大值，并给出建议的 ZScale 默认 Min/Max 传给前端。
* **客户端渲染:** 图像数据在前端以一维数组存在。当拉动右侧的拉伸滑块时，利用 JavaScript 计算 `(value - min) / (max - min) * 255` 并写入隐形 Canvas 的 `ImageData`，实现毫秒级图像刷新。反色即 `255 - value`。

### 2. 多图层闪视 (Blinking)
* 前端维护三个 Image Object。
* 侦听全局键盘事件 `keydown` (如 Tab 或 Space)。每一次按下，切换当前可见视图 `App.currentView = (App.currentView + 1) % 3`。
* 视图更新时，仅仅是更改底层画板的可见图片对象，保证视场平移、缩放等级、标注目标准确不动，完美实现找彗星/瞬变源的闪视效果。

## 五、 开发实施阶段划分 (Phase Plan)

为了最快投入生产，建议分两步走：

### 第一阶段：MVP（最小可行性原型）- 预计 1-2 周
* 搭建 FastAPI 提供本地目录遍历。
* 服务器端 FITS 解析与渲染（后端拉伸，下发 PNG 给前端展示）。
* 引入 Konva.js 实现画布加载、拖拽、缩放。
* 实现 Tab/Space 键 Old/New/New_Marked 三图无缝闪烁。
* 实现方框 (BBox) 绘制，并以 JSON 提交保存至服务器 `positive/` 或 `negative/` 目录。

### 第二阶段：纯 FITS 渲染与进阶协作 - 预计 2-3 周
* 替换后端渲染为前端 WebGL 或纯 JS 的 FITS 解析。
* 实现侧边栏双滑块：无延迟实时动态直方图拉伸和反色。
* 丰富标注工具（点、多边形）。

### 第三阶段：用户管理与版本控制 - 预计 1-2 周
* 引入完整用户鉴权系统（JWT Token 校验、用户角色区分）。
* 重构数据集分发逻辑，对系统活跃用户针对性分配不同的图库/图像队列，彻底锁死防冲突。
* 实现标注动作的全生命周期版本控制机制（右侧面板查看所有用户历史提交快照、比对标注差异、一键回滚）。
